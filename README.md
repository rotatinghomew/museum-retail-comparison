# 馆内试销与合作门店

经营演练资料均为合成数据，不涉及真实参赛者、顾客或合作方。 `data/drill.json` 为 UTF-8 JSON；顶层键为来源表名，值为行数组。日期按当地工作日历，编号是代号而非名称。 金额使用整数分；`null` 表示未取得该事实，不等于零。

到访记录的 `observed` 表示该行记录窗口完整；`visitor` 为空则没有跨渠道连接键。`target.mass` 为目标构成权重而非到访量。每次收货确认按 `known_on` 追加，不覆盖旧确认。预约占位按 `window` 和 `sku` 记；`intake` 决定交易和退款成熟范围。

## 快速开始

需要 Python 3.11+，无第三方依赖。

```bash
# 资料结构核查
python3 -m unittest discover -s tests -v

# 本轮圈选：两款、59 档、合作南店；输出 JSON 并写不可变快照
python3 -m trial.cli --data data/drill.json \
    --skus 纸域-v1 陶语-v1 --band 59档 --shops 合作南店 --write

# 追加后来收到的周报/退款流水，重新分析
python3 -m trial.cli --append data/week2.json --as-of 2026-07-30 --write

# 查看历史快照、比较最近两轮修订
python3 -m trial.cli --history
python3 -m trial.cli --diff-last

# 把某份快照标记为“已向门店引用”（内容不变）
python3 -m trial.cli --quote reports/2026-07-23-xxxx.json --quote-note "7/23 与南店口头沟通"
```

## 分析口径

### 曝光与归属

* 可比单位是 **门店 × 款式 × 价格档 × 客群层 (segment, slot)** 在 `listings`
  可订期间、`observed=True`、且不晚于分析日的到访机会。
* 同一访客只取 `(exposed_on, id)` 最早的一条符合资格曝光。重复访客、跨店
  成交、门店先统计后撤单都跟随该首个曝光；后续曝光不进分母。
* 匿名曝光（`visitor=null`）没有连接键，只计覆盖缺口，**不推测成交**。

### 成交与成熟

* 成交 = 首个曝光后 `purchase_days` 天内、同 SKU、能连到该访客的订单。
* 净留单 = 到 `refund_days` 观察期结束仍未退款的订单。
* 未到退款观察期的订单进入 `pending`：不进分子，也不从成熟分母中消失，
  单列提示，等后到流水复核。
* 完整计数但零成交是一个**结果**，不是“资料不足”；系统会输出
  `零成交（观察完整）`，不会把它归入缺口。

### 目标构成与比较

* `target.mass` 是合作方客群权重，不能拿馆内到访结构直接替代。
* 占比不为零、但没有可信观察的层只列为 `gaps`；不能用别的层填满，
  也不能删掉缺口后声称是整店结论。
* 只有所有目标层都可可信观察时，才输出整店加权估计；否则为 `null` 并说明原因。
* 款式比较只在 **所有款式都有可信观察的共同层** 上进行，输出
  `covered_mass`（覆盖了目标机会的多少）和 `uncovered_layers`。
* 用 bootstrap 给出共同层加权率区间与两两差值区间；差值区间跨零时
  `order_stable=false`，不得把排序当结论。
* 跨店差异大时，即使整店加权估计算得出，也附 `weighted_note` 说明
  “合并率仅供参考，不代表任一门店”。
* 按曝光门店拆分的敏感性表用于识别“只在部分时段记录”导致的跨店差异；
  率差过大或排序反向时不承诺整店转化。

### 场次与承诺

* `availability` 按 `known_on` 追加，分析取当前认知。
* 已确认场次若新资料显示对照款无货：`已确认场次对照款缺货`，待办是
  **补做对照款或取消场次**，不得默认该场次已产生有效证据。
* 未确认场次可重排；已确认但未实际改订的承诺不随预测移动。
* 补采名额按缺口层的目标权重排序，不按“观察最少”。同一场次必须能同时
  安排目标款与对照款才缩小缺口；只有单款不构成比较。

## 本轮演练结论

以 `2026-07-23` 为分析日、圈选 59 档两款、目标门店合作南店：

| 款 | 可谈范围 | 目标覆盖 | 整店口径 |
| --- | --- | --- | --- |
| 纸域-v1 | 可按层谈试点 | 常客/休息日 + 游客/工作日，覆盖 100% | 跨店差异大，不能承诺整店转化 |
| 陶语-v1 | 仅游客/工作日可谈 | 覆盖 55%；常客/休息日（目标权重 45%）无曝光 | 不可给整店估计 |

* 共同可信层只有 `游客/工作日`（覆盖 55% 目标机会）。纸域 16.7%、
  陶语 13.3%，但两两差值区间含 0，`order_stable=false`，**不能把先后当结论**。
* 陶语在 `常客/休息日` 没有任何曝光：该层不能被游客层填满，也不能删掉后
  声称是整店结论；下一轮应补这一层。
* 馆西/纸域/常客/休息日 7 次完整观察、零成交；这是完整计数结果，不是资料不足。
* W1（7/25，已确认）的对照款陶语在 7/21 确认无货 → 必须补做对照或取消，
  不能计为已产生有效证据。W2（8/1，未确认）可承接常客/休息日缺口；
  W3（8/3，游客/工作日）不是当前缺口，不应占用名额。
* 未到退款期的订单（如 `o97`）尚未计为净留单；匿名曝光 8 条、窗口不完整
  8 条、无法连接到合格曝光的订单 2 笔，均在 `quality`/`audit` 中单列。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `trial/engine.py` | 归属、成熟、覆盖、加权、bootstrap、跨店敏感性、审计 |
| `trial/booking.py` | 场次状态、库存冲突、补采建议与缺口待办 |
| `trial/review.py` | 快照、修订比较、引用标记、增量合并、资料质量 |
| `trial/cli.py` | 命令行入口 |
| `tests/` | 原始资料核查 + 口径回归测试 |

`reports/` 中保存每次运行的不可变快照；同一输入重跑会追加修订号，不覆盖旧文件。
快照是本地产物，默认被 `.gitignore` 排除（保留 `reports/.gitkeep`）。
